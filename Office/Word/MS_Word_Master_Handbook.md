# How to Use This Handbook

This handbook is designed to work in two ways:

1. **Learning guide:** read the sections in order while practicing in Word.
2. **Reference manual:** jump directly to a topic when you need to solve a real document problem.

Do not try to memorize every Ribbon command. Learn the underlying document model first.

```text
Content
   ↓
Paragraphs and sections
   ↓
Styles and lists
   ↓
Page layout
   ↓
References and fields
   ↓
Collaboration
   ↓
Automation
   ↓
Release quality
```

## Beginner pass

Focus first on:

- editing and selection;
- paragraph formatting;
- styles;
- tables and pictures;
- page and section breaks;
- headers, footers, and page numbers;
- automatic Table of Contents;
- comments and Track Changes;
- printing and PDF.

## Productive-user pass

Then learn:

- multilevel numbering linked to styles;
- captions and cross-references;
- templates;
- Mail Merge;
- fields;
- content controls;
- version history;
- accessibility;
- long-document maintenance.

## Power-user pass

Finally learn:

- advanced field use;
- VBA/macros;
- document properties;
- controlled forms;
- document security;
- automation architecture;
- enterprise release workflows.

## Practice rule

For every important feature, ask:

> **What problem does this solve? → What does Word store internally? → What input do I provide? → What output changes? → What can break? → How do I verify the result?**

This approach is more useful than memorizing menu paths that may move between Word versions.

# 1. What Microsoft Word Is

Microsoft Word is a **word-processing application** used to create, edit, format, review, print, and share documents.

Typical Word documents include:

- letters
- resumes and CVs
- reports
- manuals
- SOPs
- project documentation
- meeting minutes
- proposals
- contracts
- academic assignments
- books
- certificates
- labels and envelopes
- invoices and quotations
- forms
- newsletters

Word is much more than a place to type text. A professional Word document can contain structured headings, automatic numbering, tables, images, charts, captions, citations, cross-references, fields, forms, tracked revisions, comments, macros, and accessibility information.

## Word vs a plain text editor

A plain text editor mainly stores characters. Word stores content **plus document structure and formatting**.

Example text:

```text
Quarterly Report
Revenue increased by 12%.
```

In a plain text editor, `Quarterly Report` is simply text. In Word it can be `Heading 1`, which means it can automatically appear in the Navigation Pane, Table of Contents, outline structure, and cross-references.

### Key lesson

Mastering Word is not about memorizing every button. It is about understanding **structure, reusable formatting, layout, references, collaboration, and automation**.

# 2. Word Editions, Platforms, and File Types

## Common Word platforms

You may use:

- Word for Microsoft 365 on Windows
- Word 2024
- Word 2021
- Word for Mac
- Word for the web
- Word mobile apps

Core editing and formatting concepts are similar, but advanced features such as VBA, some mail-merge functions, advanced printing, and certain add-ins may be desktop-only or behave differently.

## Important file formats

### `.docx`

The standard modern Word document format. Use this for most editable documents.

Example:

```text
Employee_Handbook.docx
```

### `.doc`

Older Word format. Use only when compatibility with legacy software is required.

### `.docm`

A macro-enabled Word document.

Example:

```text
Invoice_Automation.docm
```

### `.dotx`

A reusable Word template without macros.

### `.dotm`

A reusable Word template that can contain macros.

### `.rtf`

Rich Text Format. Useful for compatibility, but it may not preserve every modern Word feature.

### `.txt`

Plain text. Most Word formatting, tables, images, and structure are lost.

### `.pdf`

A fixed-layout distribution format. Use PDF when recipients should see the final document with stable layout.

## Simple file-format rule

Use:

- `.docx` for normal documents
- `.docm` for documents containing VBA macros
- `.dotx` for templates
- `.pdf` for final distribution

## Microsoft 365 vs Word 2024

These names describe different release models.

| Edition | Mental model | Updates |
|---|---|---|
| Word for Microsoft 365 | Subscription version | Receives ongoing feature and service updates while the subscription is supported |
| Word 2024 | Perpetual release | Has the Word 2024 feature set plus supported fixes; it does not automatically become the next perpetual major release |
| Word LTSC 2024 | Commercial long-term servicing release | Designed for organizations that need a more fixed feature set |

Do not assume that a feature shown in a Microsoft 365 tutorial exists in Word 2024, Word 2021, Word for Mac, or Word for the web.

## Desktop vs web: practical decision

Word for the web is strong for everyday editing and collaboration, but desktop Word remains the safer choice for advanced document engineering.

| Task | Desktop Word | Word for the web |
|---|---|---|
| Normal writing and formatting | Excellent | Excellent |
| Real-time collaboration | Yes | Yes |
| Track Changes | Yes | Yes in current web experience, with some workflow differences |
| Advanced page/section layout | Full | More limited / feature-dependent |
| VBA macros | Create and run | Macro-enabled files can be stored/opened, but VBA does not run in the browser |
| Mail Merge | Full desktop workflow | Not a normal Word-for-the-web feature |
| Advanced fields | Full | Existing fields are preserved; advanced creation/editing can require desktop Word |
| Compare/Combine documents | Full | Use desktop Word for the full comparison workflow |

**Best practice:** if a document contains macros, complex section layouts, advanced fields, formal mail merge, or other desktop-only features, open it in desktop Word before making structural changes.

## `.odt` — OpenDocument Text

Word can work with OpenDocument Text files, but `.odt` and `.docx` do not support every feature in exactly the same way. Formatting or behavior may change when moving between Word and other ODF applications.

Use `.docx` when Word-specific fidelity matters. Use `.odt` when OpenDocument interoperability is a requirement, and verify the converted document carefully.

## Compatibility rule

Whenever you change file format or platform, check at least:

```text
Styles
Numbering
Tables
Images
Headers/footers
Fields
References
Tracked changes
Accessibility
Final pagination
```

A document that opens successfully is not automatically a document that preserved every feature perfectly.

# 4. How a Word Document Is Structured

Think of a Word document as a hierarchy:

```text
Document
├── Sections
│   ├── Paragraphs
│   │   ├── Words
│   │   └── Characters
│   ├── Tables
│   ├── Images and objects
│   ├── Fields
│   └── Content controls
└── Headers and footers
```

## Character

The smallest text unit. Character formatting includes font, size, bold, italic, color, superscript, and subscript.

## Paragraph

A paragraph ends when you press **Enter**. Paragraph formatting includes alignment, indentation, line spacing, space before/after, borders, and list settings.

A heading is also a paragraph.

## Section

A section allows one part of a document to have different page-level settings from another part.

A section can have different:

- margins
- orientation
- columns
- headers and footers
- page numbering

## Page

A page is the result of text, paragraph spacing, page size, margins, and layout settings. A page is not the primary structural unit of Word.

That is why pressing Enter repeatedly to force a new page is poor practice. Use a **Page Break**.

## Style

A named reusable formatting definition such as `Heading 1`, `Normal`, or `Caption`.

## Field

A dynamic value calculated or updated by Word, such as page number, date, cross-reference, or Table of Contents.

## Content control

An interactive placeholder used in forms and templates, such as a text field, checkbox, date picker, or drop-down list.

## The paragraph mark stores more than a visible symbol

When formatting marks are displayed, a paragraph ends with `¶`. That paragraph mark participates in paragraph formatting and document structure.

This explains why copying or deleting a paragraph mark can sometimes change formatting in a way that surprises beginners.

### Practical rule

If paragraph formatting behaves strangely:

1. turn on formatting marks;
2. inspect paragraph marks, tabs, breaks, and empty paragraphs;
3. check the applied style;
4. only then start changing fonts or spacing.

## Visible page vs logical structure

Word continuously lays content onto pages. A page can change simply because you:

- change margins;
- change font metrics;
- insert an image;
- modify paragraph spacing;
- update a field;
- switch printers or page sizes;
- add or remove text.

Therefore, **page number is an output of layout**, not a reliable way to define document structure. Headings, bookmarks, captions, fields, and sections are usually more durable references than manually typed page numbers.

# 5. Creating, Opening, Saving, and Managing Documents

## Create a new document

Typical workflow:

```text
File → New → Blank document
```

You can also start from a template.

## Save

Shortcut:

```text
Ctrl + S
```

Save frequently.

## Save As

Use Save As when you want a copy, a new filename, another location, or another file format.

Good versioned names:

```text
Project_Proposal_v01.docx
Project_Proposal_v02.docx
Project_Proposal_Approved_2026-08-20.docx
```

Avoid chaotic names such as:

```text
final.docx
final2.docx
final_final_new.docx
```

## AutoSave

When supported and stored in an appropriate cloud location such as OneDrive or SharePoint, Word can save changes automatically.

AutoSave is helpful, but it is not the same as a complete backup strategy.

## AutoRecover

AutoRecover can help restore unsaved work after crashes or unexpected restarts.

It is a recovery feature, not a replacement for saving.

## Recent documents

Word keeps a list of recent files. You can pin important documents.

## Compatibility Mode

Older documents may open in Compatibility Mode. Some newer features may be limited until the file is converted to a modern format.

## Save, AutoSave, AutoRecover, and Version History are different

| Feature | Main purpose | What it does not replace |
|---|---|---|
| Save | Writes current changes to the file | Backup/version strategy |
| Save As | Creates a new name/location/format | Change tracking |
| AutoSave | Continuously saves supported cloud documents | Independent backup |
| AutoRecover | Helps recover work after an unexpected interruption | Normal saving |
| Version History | Lets you inspect/restore earlier cloud versions when supported | Formal document approval/version control |

### Scenario: you accidentally delete two pages

If the document is stored in a supported OneDrive/SharePoint location, version history may be more useful than repeatedly pressing Undo, especially if the deletion happened earlier.

### Scenario: Word crashes before you save

AutoRecover may offer a recovered copy. Save that recovered document immediately under an intentional filename and then verify its contents.

## Safe document-version workflow

For an important controlled document:

```text
Working copy
   ↓
Frequent Save / AutoSave
   ↓
Cloud or repository version history where approved
   ↓
Explicit reviewed/approved version
   ↓
Final distribution copy or PDF
```

Do not use filenames such as `final_final2.docx` as a substitute for a deliberate versioning process.

## Save-format warning

Changing a filename extension manually does not convert a document.

Bad:

```text
report.docx → rename to report.pdf
```

Correct:

> Use Word's Save As / Export workflow to create the target format, then open the generated file and verify it.

# 6. Selecting and Editing Text

## Useful selection actions

- drag over text to select it
- double-click a word
- use Shift + Arrow to extend selection
- use Ctrl + Shift + Arrow to select word by word

## Select all

```text
Ctrl + A
```

## Move quickly

```text
Ctrl + Left/Right
```

Moves by word.

```text
Ctrl + Up/Down
```

Moves by paragraph.

```text
Ctrl + Home
```

Beginning of document.

```text
Ctrl + End
```

End of document.

## Delete efficiently

```text
Ctrl + Backspace
```

Deletes the previous word.

```text
Ctrl + Delete
```

Deletes the next word.

## Undo and Redo

```text
Ctrl + Z
Ctrl + Y
```

## Paragraph break vs manual line break

These look similar on screen but mean different things.

### Enter — new paragraph

Pressing **Enter** creates a new paragraph. The new paragraph can have its own paragraph formatting, style behavior, list behavior, spacing, and pagination rules.

### Shift + Enter — manual line break

A manual line break moves text to the next line **without creating a new paragraph**.

Use it only when you truly need another line inside the same paragraph, for example in a tightly controlled address or poem layout.

### Common mistake

Do not use manual line breaks everywhere merely to avoid paragraph spacing. Fix the paragraph style instead.

## Backspace vs Delete

- **Backspace** removes content before the insertion point.
- **Delete** removes content after the insertion point.
- `Ctrl + Backspace` and `Ctrl + Delete` remove larger word-based units and are useful when editing quickly.

## Editing safety habit

Before performing a large deletion, replacement, or move in an important document:

1. save the file;
2. make sure the correct content is selected;
3. perform the edit;
4. immediately inspect surrounding headings, list numbering, and section breaks.

# 7. Clipboard, Copy, Paste, and Paste Options

## Basic shortcuts

```text
Ctrl + C → Copy
Ctrl + X → Cut
Ctrl + V → Paste
```

## Why Paste Options matter

Text copied from a website, email, Excel, or another Word file may bring unwanted formatting.

Common choices:

### Keep Source Formatting

Preserves the original formatting.

### Merge Formatting

Adapts the pasted material to the destination while preserving basic emphasis.

### Keep Text Only

Removes most source formatting.

### Scenario: copying from a website

If the website contains blue text, odd fonts, and background colors but you only need the words, choose **Keep Text Only**, then apply your document styles.

## Format Painter

Copies formatting rather than content.

Good for a one-off formatting fix. If the same appearance must be reused throughout the document, use a **Style** instead.

# 8. Find, Replace, Go To, and Advanced Search

## Find

```text
Ctrl + F
```

Useful for finding text and navigating a large document.

## Replace

```text
Ctrl + H
```

Example:

```text
Find: FY25
Replace with: FY26
```

Use Replace carefully. A short search term can match unintended text.

## Find formatting

Word can search for formatting as well as text.

Example use case:

> Find every paragraph formatted as red bold text and replace its formatting with a proper custom style.

## Special characters

Advanced Find/Replace can work with paragraph marks, tabs, manual line breaks, page breaks, and other special characters.

## Go To

```text
Ctrl + G
```

Can jump to items such as a page, section, line, bookmark, footnote, or comment.

## Wildcards

Word supports advanced wildcard matching for complex text cleanup. Test wildcard replacements on a copy first.

## A safe Replace workflow

Global Replace is powerful because it can change hundreds of locations at once. That is also why it can damage a document quickly.

Use this sequence:

```text
Save
↓
Find first occurrence
↓
Confirm the search pattern is specific enough
↓
Replace a few examples manually
↓
Inspect results
↓
Use Replace All only when confident
```

### Example: dangerous short replacement

Searching for a very short fragment such as `IT` may also match those letters inside unrelated words. Prefer a more specific search whenever possible.

## Wildcards are not regular expressions

Word's **Use wildcards** feature has its own pattern rules. Do not copy a JavaScript, Python, or PCRE regular expression and assume it means the same thing in Word.

For complex wildcard cleanup:

1. work on a copy;
2. test against a few known examples;
3. inspect both matching and nonmatching cases;
4. only then run a broad replacement.

# 10. Paragraph Formatting

Paragraph formatting affects the entire paragraph.

## Alignment

### Left

Best default for most body text.

### Center

Useful for titles, not for long paragraphs.

### Right

Useful for dates or special layout elements.

### Justify

Aligns both edges. It can look formal but may create uneven spacing.

## Line spacing

Controls space between lines within a paragraph.

Examples:

- Single
- 1.15
- 1.5
- Double

## Paragraph spacing

Use `Space Before` and `Space After` rather than pressing Enter repeatedly.

Bad:

```text
Paragraph 1
Enter
Enter
Enter
Paragraph 2
```

Better:

```text
Paragraph 1 → Space After: 12 pt
```

## Indentation

Types include:

- left indent
- right indent
- first-line indent
- hanging indent

Hanging indents are common in bibliographies.

## Keep with next

Useful for headings so a heading is not left alone at the bottom of a page.

## Keep lines together

Helps keep a paragraph on one page when possible.

## Widow/Orphan control

Helps avoid a single line of a paragraph being separated at the top or bottom of a page.

## Page break before

Useful for chapter heading styles that should always begin on a new page.

## Character formatting vs paragraph formatting

This distinction explains many Word problems.

| Question | Character formatting | Paragraph formatting |
|---|---|---|
| Applies to | Selected characters | Entire paragraph |
| Examples | Font, bold, italic, color | Alignment, indents, spacing, pagination |
| Stored around | Text runs | Paragraph and its paragraph mark |
| Typical style | Character style | Paragraph style |

### Example

If one word needs emphasis, use character formatting such as bold.

If every paragraph under a heading needs 8 pt after it, change the paragraph style rather than applying font formatting.

## Paragraph spacing vs line spacing

- **Line spacing** controls lines *inside* one paragraph.
- **Space Before/After** controls separation *between* paragraphs.

Do not add empty paragraphs just to create visual gaps. Empty paragraphs become real document content and can cause unexpected blank pages and pagination changes.

# 11. Tabs, Indents, and the Ruler

## Do not align text with repeated spaces

Bad:

```text
Name:       Ravi
Role:       Developer
Department: IT
```

Spacing can move when fonts or content change.

Use:

- tab stops
- tables
- proper alignment tools

## Tab stop types

### Left tab

Text grows to the right.

### Center tab

Text centers around the tab position.

### Right tab

Text ends at the tab position.

### Decimal tab

Aligns numeric values around the decimal point.

### Bar tab

Places a vertical line.

## Tab leaders

Example:

```text
Introduction.....................1
Security........................15
Backup..........................42
```

A Table of Contents can generate this automatically.

## Tabs vs tables: which should you use?

Use **tab stops** when you have a small number of aligned text positions on a line.

Use a **table** when the information is truly rows and columns or when each column needs its own wrapping/alignment behavior.

| Need | Better tool |
|---|---|
| Align a date at the right edge of a header | Right tab |
| Align prices at decimal points | Decimal tab |
| Create a 5-column invoice | Table |
| Build a two-column form layout | Usually table or content controls |
| Add dotted leaders manually | Tab leader, unless an automatic TOC is more appropriate |

### Common mistake

Pressing Tab repeatedly does not create a durable layout unless intentional tab stops are defined. Default tab positions may not match your design and can shift when margins change.

# 12. Styles

A **Style** is a reusable set of formatting rules. Styles are one of the most important Word concepts.

## Direct formatting approach

You manually set every heading to:

```text
18 pt
Bold
Blue
Space Before: 18 pt
Space After: 8 pt
```

If there are 50 headings, changing them later is tedious.

## Style-based approach

Apply:

```text
Heading 1
```

Then modify `Heading 1` once. Every Heading 1 can update consistently.

## Common built-in styles

- Normal
- No Spacing
- Title
- Subtitle
- Heading 1
- Heading 2
- Heading 3
- Quote
- Caption
- List Paragraph

## Why styles matter

Styles provide:

- consistency
- Navigation Pane structure
- automatic Table of Contents
- easier global redesign
- accessibility support
- outline hierarchy
- better templates

## Heading hierarchy

Example:

```text
Heading 1 → Chapter
Heading 2 → Main topic
Heading 3 → Subtopic
Heading 4 → Detailed subtopic
```

Correct hierarchy:

```text
1. Security
   1.1 Authentication
       1.1.1 Password Policy
```

## Custom styles

You can create a style such as:

```text
Warning
```

with consistent font, border, shading, and spacing.

Another example:

```text
Code Example
```

could use a monospace font, smaller size, and paragraph shading.

## Style inheritance

A style can be based on another style. Changes to the base style may influence derived styles.

## Automatically Update

Use cautiously. Automatic style updating can cause manual changes to propagate unexpectedly.

## Scenario: company SOP

Use:

```text
Document title → Title
Main sections → Heading 1
Subsections → Heading 2
Warnings → Warning style
Normal instructions → Normal
Screenshots → Caption style
```

This makes the document maintainable.

## Style types you may encounter

Word supports several style categories. The exact gallery shown depends on your document and version.

- **Paragraph styles** — affect paragraph-level formatting and can also carry character formatting.
- **Character styles** — apply to selected characters without redefining the whole paragraph.
- **Linked styles** — can behave as paragraph or character styling depending on how they are applied.
- **Table styles** — control reusable table appearance.
- **List styles** — support reusable numbering/list definitions.

For most long documents, paragraph heading styles and a deliberate body-text style provide the greatest benefit.

## Modify the style, not fifty paragraphs

If every `Heading 2` needs to change from 14 pt to 15 pt, modify `Heading 2` once.

Avoid this maintenance pattern:

```text
Select heading 1 → change
Select heading 2 → change
Select heading 3 → change
...
```

## Direct formatting does not automatically redefine a style

A paragraph can use `Heading 2` **and** contain direct formatting on top of that style.

When a paragraph looks different from other paragraphs using the same style, check whether direct formatting has been added.

### Troubleshooting sequence

```text
What style is applied?
↓
Does the style definition contain the expected formatting?
↓
Is direct formatting overriding it?
↓
Is the style based on another style that changed?
↓
Is the theme changing theme-aware fonts/colors?
```

## Best practice for enterprise templates

Keep the number of custom styles intentional. A template with 80 nearly identical styles is difficult to maintain.

Prefer semantic names such as:

```text
Warning
Procedure Step
Code Block
Document Control
```

rather than names based only on appearance such as:

```text
Blue 12pt Box
Big Red Text
```

Semantic names survive redesigns better.

# 13. Themes and Consistent Formatting

A **Theme** defines an overall design system.

Themes may contain:

- theme colors
- theme fonts
- graphical effects

## Styles vs Themes

Think:

```text
Style = formatting for a specific element
Theme = overall visual design system
```

Example:

If a heading style uses the theme heading font, changing the theme may update the heading font throughout the document.

## Best practice

Prefer theme colors and consistent style rules rather than random manual colors.

## Why themes are useful

A theme gives styles and objects a coordinated design vocabulary. If your styles use theme-aware fonts and colors, one theme change can update the visual character of the document without rebuilding every style manually.

### Theme-aware design

```text
Theme fonts/colors
       ↓
Styles
       ↓
Headings, body text, tables, shapes, charts
```

This is especially useful for organization templates, proposals, reports, and branded documents.

## What a theme does not fix

A theme does not automatically repair:

- poor heading hierarchy;
- inconsistent manually applied font colors;
- badly built tables;
- manual page-number typing;
- broken section structure;
- inaccessible reading order.

Think of a theme as the **design system**, not the document structure.

## Themes vs styles vs direct formatting

| Tool | Best use | Example |
|---|---|---|
| Theme | Document-wide design vocabulary | Corporate colors and fonts |
| Style | Reusable semantic formatting | `Heading 1`, `Warning`, `Caption` |
| Direct formatting | Small local exception | Bold one important phrase |

## Real-world scenario: company rebrand

A company changes its primary typeface and brand colors.

A well-designed template may require changes mainly to:

1. theme fonts/colors;
2. a small set of styles;
3. selected logo/brand assets.

A poorly designed document with hundreds of manually colored paragraphs may require manual cleanup throughout the file.

## Common mistakes

- applying arbitrary colors that are not part of the design system;
- using theme changes to compensate for incorrect styles;
- assuming the same theme will render identically when a required font is unavailable;
- creating a different font/color rule for every section.

## Best practice

Build in this order:

```text
Document structure
↓
Theme
↓
Styles
↓
Local exceptions
```

Do not reverse the order and try to create structure out of visual decoration.

# 14. Page Setup and Document Layout

## Margins

Margins control the printable text area and affect page count.

## Orientation

### Portrait

Best for most letters, reports, and resumes.

### Landscape

Useful for wide tables and diagrams.

## Page size

Common sizes include:

- A4
- Letter
- Legal

Use the size required by your region or organization.

## Columns

Useful for newsletters and brochure-style layouts.

Options include one, two, three, and custom columns.

## Hyphenation

Can improve text flow in narrow columns or justified text. Use carefully.

## Line numbers

Useful for legal, academic, or technical review where reviewers need to refer to exact lines.

## Page background

Includes watermark, page color, and page borders.

Use backgrounds carefully because they can affect printing and accessibility.

## Gutter and binding space

For documents that will be physically bound, you may need extra space near the binding edge. Word provides margin options for this purpose, including gutter-related settings depending on version/layout.

Do not fake binding space by pressing spaces or inserting empty text boxes.

## Mirror margins

Book-like or double-sided documents may use mirrored inside/outside margins rather than identical left/right margins. This is useful when facing pages need binding-aware spacing.

## Layout decision table

| Requirement | Main Word feature |
|---|---|
| New content starts next page, same layout | Page Break |
| One wide table needs landscape | Section Break + Landscape orientation |
| Newsletter-style text | Columns |
| Different front-matter page numbers | Section Break + page-number settings |
| Book binding | Margin / mirror / gutter options |
| Reviewers refer to exact lines | Line numbers |

## Layout troubleshooting principle

If changing one page unexpectedly changes another page, ask:

> **Are these pages in the same section?**

Many layout settings are section-level settings. Until you understand the section boundaries, changing margins, headers, orientation, or page numbering can have wider effects than expected.

# 15. Page Breaks and Section Breaks

This is one of the most important layout topics.

## Page break

A page break means:

> Start the next content on a new page.

Shortcut:

```text
Ctrl + Enter
```

Do not press Enter many times to force a new page.

## Section break

A section break creates a new section that can have different page-level settings.

Use it when you need:

- portrait followed by landscape
- different headers or footers
- different margins
- page numbering restarted
- different columns

## Common section break types

### Next Page

Starts a new section on the next page.

### Continuous

Starts a new section on the same page.

### Even Page

Starts on the next even-numbered page.

### Odd Page

Starts on the next odd-numbered page.

## Scenario: one landscape table

Desired:

```text
Page 1 → Portrait
Page 2 → Portrait
Page 3 → Landscape table
Page 4 → Portrait
```

Use:

```text
Portrait content
Section Break - Next Page
Landscape section
Section Break - Next Page
Portrait section
```

## Section-break side effects

A section break is powerful because it separates page-level settings. That power also creates complexity.

After inserting a section break, verify:

- header/footer linkage;
- page-number continuation or restart;
- page orientation;
- margins;
- columns;
- footnote/endnote behavior if relevant;
- whether an unexpected blank page was introduced.

## Continuous section break use case

A continuous section break is useful when you need a temporary layout change on the same page, such as a multi-column block inside an otherwise single-column page.

Use it sparingly. Many unnecessary continuous sections make a document difficult to diagnose.

## Deleting a section break can change formatting

When you remove a section break, Word must reconcile the section-level formatting on either side. Therefore, deleting a break can change page layout, headers/footers, or numbering.

Before deleting a section break in an important document:

1. save a copy;
2. display formatting marks;
3. note the settings on both sides;
4. delete the break;
5. verify the merged section.

# 16. Headers, Footers, and Page Numbers

Headers appear at the top of pages. Footers appear at the bottom.

Common content:

- company name
- document title
- confidentiality label
- chapter title
- page number
- date
- file name

## Different First Page

Useful when the cover page should not show the normal header/footer.

## Different Odd & Even Pages

Useful in books and manuals.

## Link to Previous

A section header/footer may be linked to the previous section.

If editing a header changes another section unexpectedly, inspect **Link to Previous**.

## Page-number formats

Examples:

```text
1, 2, 3
I, II, III
i, ii, iii
A, B, C
```

## Scenario: report front matter

Desired:

```text
Cover → no visible number
TOC → i, ii, iii
Main report → 1, 2, 3
```

This normally requires separate sections with separate page-number settings.

## How `Link to Previous` really works

Headers and footers belong to sections. A new section may initially inherit or link to the previous section's header/footer.

Therefore this sequence matters:

```text
Create section boundary
↓
Open header/footer in new section
↓
Decide whether it should remain linked
↓
Turn Link to Previous off only when independent content is required
↓
Set numbering/header content
↓
Verify several pages before and after the boundary
```

Turning off `Link to Previous` does not automatically delete the visible header/footer. It changes the relationship between sections.

## Restarting page numbers safely

For a report where front matter uses Roman numerals and the body starts at page 1:

1. place a section break between front matter and body;
2. open the body header/footer;
3. configure linkage intentionally;
4. choose the desired page-number format;
5. set the body section to start at `1` rather than continue from the previous section;
6. verify the TOC and any page fields.

## Common mistake

Do not insert manually typed page numbers in every footer. Page numbers should normally be fields so that repagination updates them.

# 17. Bullets, Numbering, and Multilevel Lists

## Bullets

Use when sequence does not matter.

## Numbering

Use when order matters.

Example:

1. Open Word.
2. Select File.
3. Select Print.

## Multilevel lists

Used for structured numbering:

```text
1. Introduction
   1.1 Purpose
   1.2 Scope
2. Security
   2.1 Authentication
       2.1.1 Password Policy
```

## Best practice for heading numbering

Link multilevel list levels to heading styles:

```text
Level 1 → Heading 1
Level 2 → Heading 2
Level 3 → Heading 3
```

This is much safer than manually typing numbers.

## Common problem: numbering restarts

Possible causes:

- copied lists
- separate list definitions
- manual numbering
- modified list settings

For formal long documents, create a deliberate multilevel-list definition linked to styles.

## Continue numbering vs restart numbering

Two numbered lists can look identical but have different list identities.

Typical requirements include:

- continue the previous list;
- restart at 1;
- start at another number;
- use hierarchical numbering connected to headings.

Use Word's numbering/list controls rather than deleting and manually typing numbers.

## Multilevel list vs manually typed outline numbers

Bad:

```text
1. Security
1.1 Authentication
1.1.1 Passwords
```

if those numbers are plain text.

Better:

```text
Heading styles
      +
Multilevel list definition
      ↓
Automatic outline numbering
```

This allows inserted sections to renumber automatically.

## List maintenance tips

- avoid copying numbered paragraphs from many unrelated documents when you need one stable numbering system;
- link formal outline levels to heading styles;
- use `Restart at 1` or `Continue Numbering` intentionally;
- inspect indents/tab positions if numbers and text drift apart;
- do not repair numbering by manually editing the displayed number unless you truly want static text.

# 18. Tables

Tables organize information into rows, columns, and cells.

## Good uses

- comparison data
- specifications
- schedules
- invoices
- structured forms
- name/value information

## Example

| Item | Quantity | Price |
|---|---:|---:|
| Keyboard | 2 | 2500 |
| Mouse | 1 | 1200 |

## Rows and columns

You can insert, delete, and rearrange rows and columns.

## Merge cells

Useful for a title that spans multiple columns. Avoid unnecessary merging, especially in accessibility-sensitive documents.

## Split cells

One cell can be divided into several cells.

## AutoFit

### AutoFit Contents

Width follows content.

### AutoFit Window

Table expands to available page width.

### Fixed Column Width

Useful for predictable layouts.

## Repeat header rows

For a table spanning many pages, repeat the header row so every page shows the column names.

## Prevent row splitting

If a row should remain together, adjust row properties.

## Table styles

Can control borders, shading, header appearance, and banded rows.

## Sort

Word can sort simple table data. Use Excel for heavy analysis.

## Formulas

Word tables support lightweight formulas such as:

```text
=SUM(ABOVE)
```

For complex calculations, use Excel.

## Convert text to table

Delimited text can be converted into a table.

## Convert table to text

Useful when removing table structure.

## Table alignment vs cell alignment

A whole table can be left, center, or right aligned. Text inside cells has its own alignment settings.

## Scenario: invoice

Use a table for:

```text
Item | Qty | Rate | Tax | Amount
```

Right-align numeric values and avoid aligning columns with spaces.


## Word table formulas: what they are for

Word table formulas are useful for **lightweight calculations inside a document**, not for building a spreadsheet model.

Example:

```text
=SUM(ABOVE)
```

### Input

Numeric values in cells above the formula cell.

### Output

A calculated numeric result displayed in the formula cell.

### When to use

- a small invoice subtotal;
- a simple quantity/amount total;
- a document table with a few calculations.

### When not to use

Use Excel when you need:

- many formulas;
- complex dependencies;
- data validation;
- large datasets;
- charts driven by changing analytical data;
- auditing and calculation transparency.

### Important update behavior

Word table calculations behave more like document fields than a full spreadsheet recalculation engine. Do not assume every formula is current after editing input cells. Update/verify calculated fields before release.

## Table vs tab stops vs Excel

| Need | Best starting tool |
|---|---|
| Small aligned text | Tab stops |
| Structured document data | Word table |
| Repeated calculations / analysis | Excel |
| Fillable document layout | Table and/or content controls |

## Accessibility warning

A visually complex table can be difficult for assistive technology. Avoid unnecessary merged cells, nested tables, and layout-only tables when a simpler structure works.

# 20. Text Wrapping, Positioning, Anchors, and Object Layout

Images and other objects can behave either like text or like floating objects.

## In Line with Text

The object behaves like a large character inside a paragraph.

Advantages:

- predictable
- moves naturally with text
- easier in long documents
- usually simpler for accessibility

For many manuals and reports, **In Line with Text** is the safest choice.

## Floating wrapping modes

Common options include:

- Square
- Tight
- Through
- Top and Bottom
- Behind Text
- In Front of Text

## Anchor

A floating object is attached to a paragraph through an anchor.

If that paragraph moves, the object may move as well.

This explains a common complaint:

> “Why did my image jump to another page?”

Often the answer involves its anchor and wrapping settings.

## Move with Text

The object follows its anchored paragraph.

## Fix Position on Page

The object can stay at a fixed page position.

Use with care because text edits may then make the layout visually confusing.

## Behind Text

Useful for:

- watermarks
- background graphics

Be careful because objects behind text may be hard to select.

## In Front of Text

Useful for deliberate overlays but can cover content.

## Scenario: software manual screenshot

Recommended structure:

```text
Procedure paragraph
Screenshot: In Line with Text
Caption below screenshot
Next paragraph
```

This is usually more stable than floating screenshots around the page.

## Object-position troubleshooting checklist

If an image “jumps,” overlaps text, or disappears from where you expected it:

1. select the object;
2. check whether it is **In Line with Text** or floating;
3. if floating, show object anchors where possible;
4. identify the paragraph holding the anchor;
5. check whether the object moves with text or is fixed on the page;
6. inspect surrounding paragraph/page breaks;
7. test after adding a few lines of text above the object.

### Stable-document rule

For reports, SOPs, manuals, and policies, prefer the simplest positioning model that satisfies the design. Complex floating layouts create more maintenance work later.

### Use floating objects when

- you are creating a brochure-like page;
- a callout must sit beside text;
- a shape must overlay another object intentionally.

### Avoid floating objects when

- the document will receive frequent text edits;
- accessibility/reading order is critical;
- a screenshot simply needs to appear between two paragraphs.

# 22. Long Documents and the Navigation Pane

The Navigation Pane is one of the most useful Word features for long documents.

Common shortcut:

```text
Ctrl + F
```

When proper heading styles are used, Word can show a structured outline such as:

```text
Introduction
Requirements
  Functional Requirements
  Security Requirements
Architecture
Deployment
Troubleshooting
```

## Uses

You can use the Navigation Pane to:

- jump to headings
- search the document
- view page thumbnails
- understand document structure
- reorganize heading-based sections in supported desktop versions

## Important rule

Text that merely looks like a heading is not necessarily a real heading.

This:

```text
18 pt + bold + blue
```

is only direct formatting.

This:

```text
Heading 1
```

provides structure.

## Navigation Pane vs Outline view

The Navigation Pane is excellent for normal long-document navigation and heading-based reorganization.

Desktop Word also provides **Outline view**, which is useful when you want to focus heavily on heading levels and document hierarchy rather than final page appearance.

Use the Navigation Pane for day-to-day movement. Use Outline view when you need to inspect or reorganize the logical hierarchy of a very large document.

## Long-document structure audit

Before formatting a 200-page document, inspect the heading tree:

```text
Heading 1
  Heading 2
    Heading 3
  Heading 2
Heading 1
```

Ask:

- Are heading levels skipped without a real structural reason?
- Are there “fake headings” made only with bold/size?
- Are chapters consistently Heading 1?
- Is body text accidentally using a heading style?

Fix structure before building the TOC.

# 23. Table of Contents

A Table of Contents (TOC) should normally be automatic.

## How Word builds it

By default, Word usually reads heading styles.

Example:

```text
Heading 1 → TOC Level 1
Heading 2 → TOC Level 2
Heading 3 → TOC Level 3
```

## Correct workflow

1. Apply proper heading styles.
2. Insert an automatic Table of Contents.
3. Continue editing.
4. Update the TOC before release.

## Update Page Numbers Only

Use this when only pagination changed and heading text/structure did not.

## Update Entire Table

Use this when headings were:

- added
- deleted
- renamed
- reorganized

## Manual TOC problem

Bad:

```text
Introduction........1
Security............9
Backup..............27
```

If content changes, those numbers become wrong.

Automatic TOC fields can update.

## Custom TOC

You can control:

- number of levels
- page numbers
- tab leaders
- styles used
- formatting

## TOC troubleshooting table

| Problem | Likely cause | Fix |
|---|---|---|
| Heading missing | Wrong style / TOC level | Apply correct heading style or custom TOC mapping |
| Wrong page number | TOC not updated | Update the TOC |
| Old heading still listed | Only page numbers were updated | Update the entire table |
| Too many levels | TOC configured too deeply | Reduce included levels |
| Strange formatting | TOC styles were modified or direct formatting was applied | Modify the appropriate TOC styles deliberately |

## TOC content vs TOC appearance

These are separate problems.

- **Content problem:** wrong headings are included.
- **Appearance problem:** the entries are correct but font/spacing/tab leaders look wrong.

Fix content through heading structure/TOC settings. Fix appearance through TOC styles rather than manually formatting every generated entry.

## Final-release habit

Never assume the TOC is current merely because it looks plausible. Update it during the release checklist after pagination has stabilized.

# 24. Captions, Cross-References, and Table of Figures

## Caption

A caption labels a figure, table, equation, or other numbered item.

Example:

```text
Figure 1: System Architecture
Table 4: Quarterly Revenue
```

Use Word's caption feature rather than manually typing numbers.

Why?

If a new figure is inserted earlier, automatic captions can be renumbered.

## Cross-reference

A cross-reference points to another item in the same document.

Examples:

```text
See Figure 7.
See Table 3.
See Section 4.2.
```

A cross-reference can update when numbering changes.

## Table of Figures

A Table of Figures automatically lists captioned objects.

Example:

```text
Figure 1 System Architecture........4
Figure 2 Authentication Flow........9
Figure 3 Deployment Model..........18
```

## Real-world benefit

Suppose you manually type:

```text
See diagram on page 43.
```

Later the diagram moves to page 48.

The reference is now wrong.

A proper cross-reference can update automatically.

## Caption vs bookmark vs cross-reference

These tools solve different problems.

| Feature | Purpose | Example |
|---|---|---|
| Caption | Give an object a managed label/number | `Figure 7: Login Screen` |
| Bookmark | Mark a location or selection | `SecurityRequirements` |
| Cross-reference | Insert a dynamic reference to another item | `See Figure 7` |

### Why this combination matters

A caption provides the managed target. A cross-reference inserts a field that can update when numbering changes.

Do not manually type `Figure 7` repeatedly throughout a long document if the figure number can change.

# 26. Indexes and Other Reference Tools

## Index

An index helps readers find important terms.

Example:

```text
Authentication, 17, 24
Backup, 31–37
Database, 10, 14, 42
```

Basic process:

1. Mark important index entries.
2. Insert the index.
3. Update the index after document changes.

## Table of Authorities

This feature is especially useful in legal documents for organizing references to legal authorities such as:

- cases
- statutes
- regulations

The exact workflow may differ by edition/platform.

## What an index is — and what it is not

A Table of Contents reflects **document structure**. An index reflects **important concepts and where they appear**.

Example:

```text
Table of Contents → “4. Security Architecture”
Index → “authentication, 18, 27, 91”
```

A good index is curated. Word can generate the index layout, but a human still decides which concepts readers are likely to search for.

## Basic index workflow in more detail

```text
Identify important term
↓
Mark entry
↓
Choose main entry / subentry / cross-reference as appropriate
↓
Repeat throughout document
↓
Insert Index
↓
Update before release
↓
Read the generated index like a user
```

## Main entries and subentries

Conceptually:

```text
Security
    authentication
    authorization
    encryption
```

Subentries help prevent a large topic from becoming one meaningless list of page numbers.

## Index vs Find

`Ctrl + F` is excellent when a reader knows the exact word used in the document.

An index is more useful when you want curated navigation across related concepts, alternate terminology, or printed material.

## Common mistakes

- indexing almost every word;
- failing to index synonyms or reader-facing terminology;
- leaving obsolete index entries after major edits;
- assuming a generated index is correct without reviewing it;
- manually typing the final page numbers.

## Table of Authorities

A Table of Authorities is specialized for legal citations. Use it only when your legal-document workflow requires it; do not confuse it with a bibliography or ordinary index.


```text

↓
Track Changes enabled
↓
Reviewer edits and comments
↓
Author reviews each revision
↓

↓
Final verification
```

# 30. Compare, Combine, and Version Review

## Compare

Useful when two document copies were edited independently.

Example:

```text
Contract_Original.docx
Contract_Client_Edited.docx
```

Word can compare them and show changes.

## Combine

Can help merge revisions from multiple reviewers into a review document.

## Scenario

You sent:

```text
Policy_v1.docx
```

A reviewer returned:

```text
Policy_Reviewed.docx
```

but Track Changes was not enabled.

Use **Compare** to identify differences rather than reading both documents line by line.

## Best practice

When possible, use controlled coauthoring, version history, or Track Changes rather than circulating many uncontrolled copies.

## Compare vs Combine vs Side by Side

| Tool | Main question | Output |
|---|---|---|
| Compare | “What changed between these two versions?” | A comparison document showing differences as revisions |
| Combine | “How do I bring reviewer revisions from copies together?” | A combined review document |
| View Side by Side | “I want to inspect both files visually.” | No merged change set; just synchronized/parallel viewing where supported |

## Compare workflow

```text
Original document
      +
Revised document
      ↓
Compare
      ↓
New comparison document with revision marks
```

Use Compare when Track Changes was not used or when you need an independent difference check.

## Combine workflow

```text
Original sent for review
      +
Reviewer copy
      ↓
Combine
      ↓
Consolidated document with revisions
```

If several reviewers returned separate copies, combine deliberately one copy at a time and save the consolidated result between major steps.

## Important safety rule

Prefer showing comparison changes in a **new document** when possible. This helps keep the source copies unchanged and gives you a clean review artifact.

## When not to use Compare/Combine

If your team already coauthors one controlled cloud document with appropriate review/version-history processes, circulating many standalone copies may create unnecessary complexity.

# 34. Quick Parts, AutoText, and Building Blocks

These features help you reuse content.

## Quick Parts

Useful for inserting reusable items and document properties.

## AutoText

Useful for frequently repeated blocks of text.

Example:

```text
Please provide the incident ID, screenshot, exact timestamp, and steps to reproduce the issue.
```

Instead of typing this every time, store it as reusable content.

## Building Blocks

Word uses reusable building-block concepts for things such as:

- cover pages
- headers
- footers
- text snippets

## Good use cases

- legal disclaimers
- signature blocks
- company addresses
- recurring instructions
- standard contract clauses

## Quick Parts vs AutoText vs Building Blocks vs fields

These terms overlap, which can confuse beginners.

| Concept | Mental model | Best example |
|---|---|---|
| Building Block | General reusable-content architecture | Cover page, header, reusable content block |
| AutoText | Reusable text/content entry | Standard disclaimer paragraph |
| Quick Parts | UI/gallery for reusable parts and properties | Insert saved content or document property |
| Field | Dynamic value calculated/read by Word | Page number, filename, document property |

A saved disclaimer is reusable **content**. A page number is dynamic **data**. They should not be treated as the same thing.

## Input and output example

Suppose you save this as reusable AutoText:

```text
Confidential — Internal Use Only
```

**Input:** the saved building-block entry name.  
**Output:** Word inserts the stored content at the insertion point.

Compare that with a document-property field:

```text
Document Owner: { DOCPROPERTY ... }
```

**Input:** a document property.  
**Output:** Word displays the property's current value when the field is updated.

## When to use which approach

- repeated static clause → AutoText/building block;
- document title/owner/version shown in several places → document property + field;
- reusable document design → template;
- user-entered controlled value → content control;
- repeated logic across many files → consider automation.

## Common mistake

Do not create ten manually edited copies of the same boilerplate paragraph when the content is supposed to stay standardized. Reusable building blocks or a template reduce drift.

# 35. Fields and Field Codes

Fields are dynamic elements whose displayed value can be generated or updated by Word.

Common field concepts include:

```text
PAGE
NUMPAGES
DATE
FILENAME
AUTHOR
TITLE
REF
SEQ
STYLEREF
DOCPROPERTY
TOC
```

## PAGE

Displays the current page number.

## NUMPAGES

Displays the total number of pages.

Example concept:

```text
Page { PAGE } of { NUMPAGES }
```

Possible result:

```text
Page 5 of 27
```

## DATE

Displays a date based on field settings.

Be careful: a dynamic date can change later. If you need a permanent historical date, use a fixed value rather than a dynamic field.

## FILENAME

Displays the document filename.

Useful in controlled documents and internal drafts.

## DOCPROPERTY

Can display document properties such as:

- Title
- Author
- Company
- custom document properties

## STYLEREF

Can display text from a nearby paragraph using a particular style.

Common use case:

> Automatically display the current chapter heading in a running header.

## SEQ

Creates sequences for custom numbering.

## REF

References bookmark content or other reference targets.

## Updating fields

Common command:

```text
F9
```

A common workflow is:

```text
Ctrl + A
F9
```

However, headers, footers, text boxes, and other document “stories” can sometimes require additional updating.

## Field codes vs field results

Word can display either the generated result or the underlying field code. Viewing field codes is useful for troubleshooting advanced documents.

## Why fields matter

They reduce fragile manually typed values.

Instead of typing:

```text
Page 3 of 44
```

use fields so the values update when the document changes.

## Field anatomy

A field has two important views:

```text
Field code   → instruction to Word
Field result → value currently displayed
```

Conceptual example:

```text
Code:   { PAGE }
Result: 5
```

The code is the instruction. The result is the current output.

## Inputs and outputs of common fields

| Field | Input / source | Output |
|---|---|---|
| `PAGE` | Current page context | Current page number |
| `NUMPAGES` | Whole document pagination | Total page count |
| `FILENAME` | Current file metadata | File name/path depending on field configuration |
| `DOCPROPERTY` | Built-in/custom property | Property value |
| `REF` | Reference target such as a bookmark | Referenced content/value |
| `STYLEREF` | Text using a specified style in relevant context | Matching heading/text, often used in running headers |
| `SEQ` | Sequence identifier/rules | Next sequence number |

## Field update lifecycle

Fields can become stale after edits.

Examples:

- page numbers change after repagination;
- a cross-reference changes after a new figure is inserted;
- a document-property value changes;
- a calculated table result changes after source numbers change.

Therefore the release process should include a deliberate **field update and verification** step.

## Why `Ctrl + A`, then `F9` is useful but not magical

Selecting the main document and pressing `F9` updates many fields, but Word documents can contain content in other areas such as headers, footers, text boxes, footnotes, or other internal “stories.”

For complex files, inspect important dynamic content explicitly rather than assuming one shortcut updated every possible field everywhere.

## Cross-references are fields

When you insert a cross-reference through Word's reference tools, Word typically stores it as a dynamic field-based reference. This is why a cross-reference can update when its target changes.

## Common field mistakes

- typing field braces manually instead of inserting a real field;
- converting a dynamic value to ordinary text accidentally;
- forgetting to update fields before release;
- using a dynamic date when the requirement is a fixed historical date;
- manually editing a field result instead of changing its source/instruction;
- assuming all fields update continuously like spreadsheet formulas.

# 37. Protecting Documents and Restricting Editing

Word provides multiple protection concepts. They are not all the same.

## Read-only/view-only behavior

Useful for reducing accidental edits, but not always strong security.

## Restrict Editing

Can limit permitted changes.

Possible scenarios include:

- read-only document
- controlled review
- forms where only selected regions are editable

## Allow selected regions to be edited

A document can be mostly protected while specific sections remain editable.

Example:

```text
Policy text → locked
Employee Name → editable
Manager Comment → editable
```

## Password protection / encryption

Word can protect documents with passwords in supported desktop editions.

Important:

> If you lose a strong encryption password, recovery may be difficult or impossible.

Store passwords securely.

## Protected View

Files from potentially unsafe locations may open in Protected View.

Do not automatically click **Enable Editing**. Confirm that the source is trusted.

## Mark as Final

Can indicate that a document is intended as final, but it should not be treated as strong security.

## Digital signatures

Can be used in workflows designed to verify signer identity and document integrity. Exact setup depends on certificates and organizational infrastructure.


## Protection options compared

| Feature | Primary purpose | Strong security? |
|---|---|---|
| Mark as Final | Signal “this is intended to be final” | No |
| Read-only recommendation / view behavior | Reduce casual editing | Usually no |
| Restrict Editing | Limit allowed document edits | Workflow control, not equivalent to file encryption |
| Password to open / encryption | Prevent unauthorized opening when correctly configured | Security feature; protect the password |
| Protected View | Reduce risk when opening potentially unsafe files | Security boundary/protective mode |
| Digital signature | Help verify signer/publisher and integrity according to certificate workflow | Depends on certificate/trust design |

## Editing restriction is not encryption

A document that users cannot easily edit is not automatically confidential.

Ask two separate questions:

1. **Who can open/read the file?**
2. **What can an authorized reader change?**

Encryption/access control addresses the first question. Restrict Editing addresses the second.

## Security best practice

Do not weaken Trust Center, Protected View, or macro settings simply to make warnings disappear. Understand why the warning exists and use an approved trust mechanism instead.

# 38. Accessibility

An accessible Word document can be understood and navigated by a wider range of readers, including people using screen readers, magnifiers, keyboard navigation, or other assistive technology.

Accessibility is not a final cosmetic step. Good accessibility often comes from good document structure.

## Use real heading styles

Correct:

```text
Heading 1
Heading 2
Heading 3
```

Incorrect approach:

```text
18 pt + Bold
16 pt + Bold
14 pt + Bold
```

The incorrect version may look like headings but may not provide navigation structure to assistive technology.

## Keep heading hierarchy logical

Prefer:

```text
Heading 1
  Heading 2
    Heading 3
```

Avoid jumping randomly between levels without a structural reason.

## Add useful alt text

Images that communicate important information should have meaningful alternative text.

Bad alt text:

```text
image
chart
picture1
```

Better:

```text
Bar chart showing quarterly revenue increasing from ₹10 million in Q1 to ₹16 million in Q4.
```

Decorative images can be marked decorative where supported.

## Accessible tables

Prefer:

- a simple row/column structure
- a clear header row
- minimal merging and splitting
- no unnecessary nested tables
- meaningful column headings

Screen readers use table structure to understand where values belong.

## Meaningful links

Bad:

```text
Click here
```

Better:

```text
Download the Employee Leave Policy
```

## Do not rely only on color

Bad:

```text
Red means rejected.
Green means approved.
```

A reader who cannot distinguish the colors may lose the meaning.

Better:

```text
Rejected — shown with a red status label
Approved — shown with a green status label
```

## Contrast

Text and background should have sufficient contrast.

Avoid:

```text
light gray text on a white background
```

for normal body content.

## Reading order

Complex floating objects, multiple text boxes, and decorative layouts can create confusing reading order.

A simple document structure is usually easier to make accessible.

## Accessibility Checker

Word includes an Accessibility Checker that can identify many common issues.

Use it before releasing important documents.

## Scenario: accessible policy document

Use:

- Title style for the title
- Heading 1/2/3 hierarchy
- real lists rather than manually typed dashes
- table headers
- meaningful hyperlink text
- alt text for diagrams
- sufficient contrast
- Accessibility Checker before release

# 41. Macros and VBA Automation

## When automation is valuable

Suppose every week you perform these steps:

1. Apply the company title style.
2. Insert a report date.
3. Add a standard footer.
4. Format all summary tables.
5. Save a standardized output.

If the process is stable, a macro can reduce repeated manual effort.

## Record Macro

Word can record many user actions and convert them into VBA instructions.

This is an excellent way to begin learning automation.

However, recorded macros may contain unnecessary actions, so advanced users often edit the generated VBA.

## Macro-enabled files

A document containing macros normally uses:

```text
.docm
```

A macro-enabled template normally uses:

```text
.dotm
```

## Security warning

Never enable macros in an unknown or untrusted document simply because the file asks you to.

Macros can execute code and therefore can be dangerous.

## Word object model

Simplified hierarchy:

```text
Application
└── Documents
    └── Document
        ├── Sections
        ├── Paragraphs
        ├── Tables
        ├── Bookmarks
        ├── Styles
        ├── Fields
        └── Other objects
```

## Object, Property, Method

An easy mental model:

```text
Object   = noun
Property = characteristic
Method   = action
```

Example concept:

```text
ActiveDocument.Name
ActiveDocument.Save
```

`ActiveDocument` is an object.

`Name` is a property.

`Save` is a method.

## Simple VBA example: insert a title

```vb
Sub InsertReportTitle()
    Selection.TypeText Text:="Monthly Operations Report"
    Selection.Style = ActiveDocument.Styles("Title")
End Sub
```

Conceptually:

1. type text
2. apply the Title style

## Save the active document

```vb
Sub SaveCurrentDocument()
    ActiveDocument.Save
End Sub
```

## Loop through paragraphs

```vb
Sub CountLongParagraphs()
    Dim p As Paragraph
    Dim count As Long

    For Each p In ActiveDocument.Paragraphs
        If Len(p.Range.Text) > 500 Then
            count = count + 1
        End If
    Next p

    MsgBox count
End Sub
```

This demonstrates:

- a variable
- a `For Each` loop
- paragraph objects
- a property (`Range.Text`)
- a condition

## Selection vs Range

### Selection

Represents the user's current selection/cursor.

Easy to understand but can be slower and more fragile in automation.

### Range

Represents a defined region of document content without requiring visible selection.

For robust VBA, `Range` is often preferable.

Conceptual example:

```vb
Dim r As Range
Set r = ActiveDocument.Content
r.Font.Name = "Aptos"
```

## Working with tables

Conceptually:

```vb
Dim tbl As Table
For Each tbl In ActiveDocument.Tables
    tbl.Rows(1).Range.Font.Bold = True
Next tbl
```

This can apply formatting to the first row of every table.

## Working with styles

Automation should prefer styles rather than setting dozens of direct formatting properties.

Better automation concept:

```text
Apply CompanyWarning style
```

rather than:

```text
set font
set color
set size
set border
set spacing
set shading
```

for every paragraph.

## Macro storage

Macros can be stored in:

- a macro-enabled document
- a macro-enabled template
- a global template such as `Normal.dotm`, depending on your workflow

Consider who needs the macro and where it should be available.

## Automation design principle

Do this:

```text
Understand process
↓
Standardize process
↓
Test process manually
↓
Automate
↓
Test macro on copies
↓
Deploy carefully
```

Do not automate a chaotic process you do not yet understand.

## VBA vs modern add-ins

VBA is powerful for desktop Office automation.

For cross-platform or enterprise-connected solutions, technologies such as Office Add-ins, Power Automate, Graph-based integrations, or application-specific APIs may sometimes be more suitable.

Choose based on:

- platform
- security policy
- deployment model
- maintenance requirements

## Reading a VBA procedure like a beginner

Consider:

```vb
Sub InsertReportTitle()
    Selection.TypeText Text:="Monthly Operations Report"
    Selection.Style = ActiveDocument.Styles("Title")
End Sub
```

### `Sub InsertReportTitle()`

Defines a VBA procedure named `InsertReportTitle`.

- **Input parameters:** none in this example.
- **Return value:** none; a `Sub` performs actions rather than returning a function result.
- **Side effect/output:** the active document is changed.

### `Selection.TypeText`

A method on the current `Selection` object.

- **Input:** the `Text` argument.
- **Action:** types/inserts that text at the current selection.
- **Output:** document content changes.

### `ActiveDocument.Styles("Title")`

Looks up the `Title` style in the active document's Styles collection.

The assignment:

```vb
Selection.Style = ...
```

changes the style of the current selection/paragraph context.

## `Len()` in the paragraph example

`Len()` is a VBA function.

```vb
Len(p.Range.Text)
```

- **Input:** a string.
- **Return value:** the number of characters in that string.

In Word automation, a paragraph's range commonly includes its paragraph-ending marker, so do not assume this count is identical to the number of visible letters a reader sees.

## `Option Explicit`

For maintainable VBA modules, `Option Explicit` is a useful best practice because it requires variables to be declared. This catches many typing mistakes in variable names before they silently create unintended variables.

Example:

```vb
Option Explicit

Sub CountTables()
    Dim total As Long
    total = ActiveDocument.Tables.Count
    MsgBox "Tables: " & total
End Sub
```

### Inputs and output

- `ActiveDocument.Tables.Count` reads the number of tables.
- `total` stores the value.
- `MsgBox` displays a message to the user.
- The procedure does not return a value.

## Error handling

Production macros should consider what happens when assumptions fail.

Examples:

- no document is open;
- a required style does not exist;
- a table has fewer rows than expected;
- a file cannot be saved;
- access to an external file is denied.

Do not make a macro “robust” merely by ignoring every error. Handle expected failures and report useful information.

## Modern macro security

Modern Office deployments can block VBA macros from files that originated from the internet. Organizations may also enforce macro policy centrally.

For enterprise macro distribution, safer patterns include:

- digitally signing trusted VBA projects;
- using trusted publishers under organization control;
- applying least-privilege policy;
- using trusted locations sparingly because content there can bypass important protections;
- keeping macro-enabled documents out of ordinary workflows when macros are not required.

**Never recommend “Enable all macros” as a general fix.** That removes an important security barrier.

## When VBA is the right tool

Use VBA when:

- the workflow is primarily inside desktop Word/Office;
- the process is repetitive and stable;
- organization policy permits VBA;
- deployment can be controlled;
- the macro can be tested on representative documents.

## When VBA may not be the right tool

Consider Office Add-ins, Power Automate, Graph-connected services, server-side document generation, or another application when you need:

- cross-platform web behavior;
- central service deployment;
- large-scale background processing;
- integrations that should not depend on a user's desktop Word session;
- stronger application lifecycle/deployment controls.

## VBA testing checklist

- [ ] test on copies, never the only original;
- [ ] test empty/minimum/large documents;
- [ ] test missing styles/tables/bookmarks;
- [ ] test save failures and permissions;
- [ ] inspect the final document, not only the absence of a VBA error;
- [ ] document what the macro changes;
- [ ] sign/deploy according to organizational policy.

- numbers

When using AI at work, follow your organization's rules for:

- confidential information
- client data
- personal data
- restricted documents
- approved AI systems

```text
Use Copilot to draft/refine content
            ↓

            ↓

            ↓

            ↓

```

## Referencing existing material

Depending on your license, platform, permissions, and current rollout, Copilot in Word can use document context and may allow references to other accessible work files or related context.

> Give the AI the source material it should use, then tell it not to invent missing facts.

Example:

```text
Using only the attached/available project-status material,
create a 150-word executive update.
```

- produce a first draft from an approved outline;

- legal wording;
- contractual commitments;
- financial values;
- HR decisions;

May contain user-interface and personalization settings.

## Display

Can control things such as:

- display behavior
- printing/display settings

## Proofing

Controls spelling, grammar, AutoCorrect, and related settings.

## Save

Can contain:

- AutoRecover settings
- default locations
- default file format

## Language

Controls editing, display, and proofing languages.

## Advanced

Contains many detailed settings related to:

- editing
- copy/paste
- document display
- image behavior
- printing
- layout

## Customize Ribbon

Use this to add/remove tabs and enable the **Developer** tab.

## Quick Access Toolbar

Add frequently used commands.

Useful power-user choices:

- Save As
- Print Preview
- Show All Formatting Marks
- Insert Table
- Update Fields

## Add-ins

Manage installed add-ins.

If Word behaves unusually after installing an add-in, troubleshooting may include temporarily disabling the add-in.

## Trust Center and security

Controls security-sensitive behavior such as macro handling and Protected View.

Do not disable security protections simply to remove warnings.

## Options are application settings, not document formatting

This distinction matters.

Changing a paragraph style affects the document. Changing many items in **Word Options** can affect how Word behaves across multiple documents for that user profile.

Before changing a global option, ask:

> Is this document wrong, or is the Word application configured differently?

## Advanced settings: change intentionally

The Advanced page contains many behaviors that can alter editing, pasting, image insertion, display, printing, and compatibility.

When troubleshooting:

1. record the existing setting;
2. change one thing at a time;
3. reproduce the issue;
4. revert the change if it did not help.

Randomly changing ten Advanced options makes root-cause diagnosis harder.

## Add-ins troubleshooting

If Word becomes slow, crashes, or behaves strangely after an add-in change:

```text
Reproduce problem
↓
Check whether problem occurs in a clean/safe test state
↓
Disable one suspect add-in according to policy
↓
Retest
↓
Update/remove/repair only when evidence supports it
```

Do not permanently disable organization-required security or compliance add-ins without approval.

## Trust Center principle

Trust Center settings exist to control risk. Treat changes there as security changes, not ordinary personalization.

Especially avoid broad changes such as enabling all macros or marking large untrusted folders as trusted merely to remove warnings.

# 45. Common Problems and Troubleshooting

Word problems become easier when you diagnose the underlying structure instead of randomly clicking formatting buttons.

## Problem: blank page will not disappear

Possible causes:

- extra paragraph marks
- manual page break
- section break
- paragraph with `Page Break Before`
- final paragraph after a table

First turn on formatting marks:

```text
Ctrl + Shift + 8
```

Then inspect the page.

## Problem: strange dots and paragraph symbols appear

Formatting marks are enabled.

Examples:

```text
·  = space
→  = tab
¶  = paragraph mark
```

They normally do not print.

They are extremely useful for debugging.

## Problem: image jumps around

Possible causes:

- floating wrapping mode
- anchor location
- Move with Text setting
- paragraph moved

For stable documents, try:

```text
In Line with Text
```

## Problem: header changes in another section

Check:

```text
Link to Previous
```

## Problem: page number restarts unexpectedly

Check:

- section breaks
- page-number format
- `Start at` vs `Continue from previous section`

## Problem: heading not appearing in TOC

Check:

- does it use a real heading style?
- is that style included in the TOC?
- has the entire TOC been updated?

## Problem: TOC has wrong page numbers

Update the TOC.

If content structure changed, update the **entire table**, not only page numbers.

## Problem: numbered headings restart or become inconsistent

Possible causes:

- manual numbering
- copied list definitions
- independent multilevel lists

For important documents, use one carefully defined multilevel list linked to heading styles.

## Problem: pasted text looks completely different

Use paste options such as:

```text
Merge Formatting
Keep Text Only
```

Then apply document styles.

## Problem: a table row splits across pages

Check table row properties and paragraph pagination settings.

## Problem: a heading is stranded at bottom of page

Use `Keep with next` in the heading style.

## Problem: document is unexpectedly large

Possible causes:

- high-resolution images
- embedded objects
- large embedded spreadsheets
- many tracked revisions
- unnecessary media
- embedded fonts

Possible solutions:

- compress images appropriately
- remove unnecessary objects
- finalize revisions
- link data where suitable instead of embedding huge copies

## Problem: document looks different on another PC

Possible causes:

- missing fonts
- different Word version
- printer-driver differences
- compatibility mode
- different page size
- fields updated differently

For stable final distribution, use PDF after verification.

## Problem: text refuses to move up even after deleting blank lines

Check:

- Page Break Before
- Keep with Next
- Keep Lines Together
- page break
- section break

## Problem: footer page numbers are wrong after inserting landscape page

The landscape page probably created a new section. Verify:

- section numbering settings
- Link to Previous
- page-number continuation

## Problem: comments seem gone but file still has revisions

Comments and Track Changes are separate systems. Review both.

## Problem: Word says file is read-only

Possible causes:

- view-only sharing permission
- Restricted Editing
- Protected View
- read-only file attribute
- file opened by another process/user
- organization's protection policy

Do not bypass organizational restrictions without authorization.

## Problem: macros do not run

Possible causes:

- file is `.docx` instead of `.docm`
- macro security settings
- document is from an untrusted source/location
- code error
- macro stored in a different template

Never lower macro security globally just to make one unknown macro run.

## Universal Word troubleshooting sequence

When you do not know the cause, use this order:

```text
1. Save a copy
2. Turn on formatting marks
3. Identify the exact scope of the problem
4. Check applied style
5. Check paragraph settings
6. Check section boundaries
7. Check object wrapping/anchors if visuals are involved
8. Update fields/TOC if dynamic content is wrong
9. Compare against a known-good document/template
10. Test add-ins/application settings only if the document structure looks correct
```

## Diagnose document-specific vs application-wide problems

Ask:

- Does the problem happen in only one document?
- Does it happen in a brand-new blank document?
- Does another user see the same issue?
- Does the same file behave differently in desktop Word vs Word for the web?

If only one file is affected, investigate that document's structure first. If every document is affected, application settings, add-ins, fonts, printer drivers, or Office installation issues become more plausible.

## Do not destroy evidence too early

Before deleting section breaks, clearing all formatting, accepting all revisions, or converting formats, save a copy. Those actions can remove information that helps explain the original problem.

# 46. Working with Large and Complex Documents

Large Word documents need more discipline than short letters.

Examples:

- 200-page SOP manual
- thesis
- technical handbook
- policy library
- book manuscript
- large proposal

## Plan the structure first

Before writing hundreds of pages, define:

```text
Title
Heading 1
Heading 2
Heading 3
Body
Caption
Note
Warning
Code
Table style
```

## Use styles from the beginning

Do not manually format 300 headings.

## Use automatic numbering and references

Prefer:

- multilevel headings
- automatic TOC
- automatic captions
- cross-references
- fields

## Use section breaks deliberately

Too many unnecessary sections cause complexity.

Before inserting a section break, ask:

> Do I need different page-level formatting here?

If not, a page break may be enough.

## Optimize images

Do not paste huge high-resolution screenshots when the displayed image is small.

Keep an original image archive separately if full-quality sources are important.

## Use the Navigation Pane

This makes it easier to move through a large structured document.

## Use captions

Captions make automatic numbering and cross-references possible.

## Avoid manually typed “See page X” references

Use cross-references.

## Break work into controlled releases

Example:

```text
Draft v0.1
Internal Review v0.2
Approved v1.0
Minor Update v1.1
Major Revision v2.0
```

Use your organization's real versioning policy where one exists.

## Master Documents feature caution

Word has historically included a Master Document/subdocument feature for managing large documents. Complex master-document workflows can be difficult to maintain and are not necessary for most users.

For many teams, safer alternatives include:

- one well-structured document
- multiple controlled source documents combined during publishing
- document-management systems
- SharePoint/version-controlled workflows

Choose the approach appropriate to your organization.

## Large-document finalization routine

1. Save a controlled copy.
2. Resolve revisions.
3. Update all fields.
4. Update TOC.
5. Update tables of figures.
6. Check cross-references.
7. Run proofing.
8. Run accessibility checks.
9. Inspect metadata.
10. Print preview.
11. Export PDF.
12. Verify PDF.

## Large-document performance strategy

A large file can become slow because of several different factors:

- many high-resolution images;
- complex floating objects;
- huge tables;
- extensive tracked changes/comments;
- many fields/cross-references;
- embedded objects;
- add-ins/macros;
- document corruption or accumulated legacy formatting.

Do not assume file size alone explains performance.

## Safer optimization order

1. save a backup;
2. resolve unnecessary tracked revisions/comments if the review phase is finished;
3. optimize oversized images while preserving originals elsewhere;
4. reduce unnecessary floating-object complexity;
5. inspect problematic tables and embedded objects;
6. verify styles/sections rather than applying mass direct formatting;
7. test whether add-ins contribute to the slowdown;
8. only then consider more invasive repair/rebuild steps.

## Chapter files vs one file

For extremely large publications, teams sometimes split content into controlled chapter files and assemble/publish through a defined process.

Do this only when you have a clear publishing/version-control strategy. Splitting a document can complicate cross-references, numbering, TOCs, and review if done casually.

For many business manuals and reports, one well-structured `.docx` is easier to maintain than a collection of loosely managed chapter copies.

# 47. Professional Document Design Principles

Knowing Word commands does not automatically create a professional document.

Good design supports communication.

## Consistency

Use consistent:

- fonts
- heading hierarchy
- spacing
- colors
- table styles
- captions
- terminology

## Hierarchy

A reader should immediately understand the difference between:

```text
Title
Heading 1
Heading 2
Heading 3
Body text
Caption
Note
```

## White space

Do not fill every area with text.

White space improves readability and helps separate ideas.

## Alignment

Use deliberate alignment tools instead of random spaces.

## Contrast

Headings and important elements should be visually distinguishable from body text.

## Repetition

Repeat the same visual rules.

Example:

> Every warning should use the same Warning style.

## Proximity

Keep related elements near one another.

Example:

> Keep a figure caption close to its figure.

## Simplicity

Formal documents rarely need:

- six fonts
- ten colors
- heavy WordArt
- decorative shapes everywhere

A restrained design is usually more professional.

## Typography rule of thumb

Use typography to communicate structure, not to decorate every sentence.

## Tables as information, not decoration

Tables are best for genuinely tabular information.

Do not place every paragraph inside a table simply to create boxes unless the design requires it.

# 49. Common Beginner Mistakes

## Mistake 1: pressing Enter repeatedly to move to a new page

Use:

```text
Ctrl + Enter
```

## Mistake 2: using spaces for alignment

Use:

- tab stops
- tables
- paragraph alignment

## Mistake 3: manually formatting every heading

Use Styles.

## Mistake 4: manually typing a Table of Contents

Use automatic TOC.

## Mistake 5: manually numbering figures

Use Captions.

## Mistake 6: manually typing page references

Use Cross-references.

## Mistake 7: ignoring section breaks

Sections control headers, footers, page numbering, orientation, margins, and columns.

## Mistake 8: confusing a page break with a section break

Use a section break only when page-level formatting must change.

## Mistake 9: hiding Track Changes instead of resolving revisions

Accept or reject intended changes.

## Mistake 10: copying website formatting everywhere

Use controlled Paste Options.

## Mistake 11: resizing images incorrectly

Preserve aspect ratio.

## Mistake 12: using too many fonts and colors

Use styles and themes.

## Mistake 13: making headings with bold only

Use structural heading styles.

## Mistake 14: treating Word like Excel

Word tables are useful, but use Excel for heavy calculations and data analysis.

## Mistake 15: treating Excel like Word

Long narrative reports, formal policies, and structured documents are usually better in Word.

## Mistake 16: manually changing every repeated document value

Use document properties, fields, Quick Parts, or templates where appropriate.

## Mistake 17: enabling unknown macros

Only enable trusted code.

## Mistake 18: exporting PDF without checking it

Always inspect the actual final file.

## Mistake 19: confusing AutoSave with backup

AutoSave can also save an unwanted change quickly. Use version history/backups where appropriate.

## Mistake 20: adding section breaks “just in case”

Every section adds another boundary for headers, footers, numbering, margins, and layout. Insert one only when a section-level difference is required.

## Mistake 21: using floating text boxes for the entire report

This can make editing, reading order, accessibility, and pagination difficult. Use ordinary document flow unless a positioned layout is genuinely required.

## Mistake 22: using Print to PDF when an accessible tagged PDF is required

Use Word's appropriate PDF export/save workflow and verify the resulting PDF's accessibility structure.

## Mistake 23: trusting AI-generated text because it sounds professional

Professional tone does not prove factual correctness. Verify names, numbers, claims, citations, and policy-sensitive content.

# 50. Best Practices

## Writing best practices

- use clear headings
- use concise paragraphs
- prefer lists for sequences or groups
- use consistent terminology
- avoid unnecessary jargon

## Formatting best practices

- use styles
- use paragraph spacing
- use theme-aware fonts/colors
- avoid manual spaces for alignment
- use direct formatting only for small exceptions

## Long-document best practices

- design heading hierarchy first
- use Navigation Pane
- automate numbering
- automate references
- use section breaks only when needed
- use captions for numbered visuals

## Collaboration best practices

- use comments for discussion
- use Track Changes for edits
- use shared documents/version history where appropriate
- compare uncontrolled copies when necessary
- finalize revisions before release

## Security best practices

- do not enable unknown macros
- respect Protected View
- use correct sharing permissions
- encrypt sensitive files when required by policy
- inspect metadata before external release when appropriate

## Accessibility best practices

- use structural headings
- add meaningful alt text
- create simple tables
- use descriptive links
- do not rely on color alone
- run Accessibility Checker

## Automation best practices

- automate stable processes
- use styles rather than formatting every item through code
- test macros on copies
- document important macros
- respect organizational security policy

## Final-release best practices

Before sending:

```text
Update fields
Update TOC
Resolve revisions
Check comments
Run proofing
Run accessibility check
Inspect metadata
Print preview
Export final format
Verify final format
```

## Maintainability best practices

A document is well designed when another skilled user can safely update it later.

Prefer:

```text
Semantic style names
Automatic numbering
Dynamic references
Document properties
Reusable templates
Simple object layout
Clear section boundaries
```

over:

```text
Manual font changes everywhere
Typed figure numbers
Typed page references
Repeated copied boilerplate
Random text boxes
Unexplained section breaks
```

## Verification best practice

For high-value documents, validate at three levels:

1. **Content** — facts, names, numbers, wording.
2. **Structure** — styles, sections, numbering, references, accessibility.
3. **Output** — final `.docx`, printed result, or exported PDF.

A document can be correct at one level and broken at another.

# Final Mental Model

To master Microsoft Word, remember these seven layers:

```text
1. CONTENT
   What you write

2. STRUCTURE
   Headings, paragraphs, sections, lists, tables

3. STYLE
   Consistent reusable formatting

4. LAYOUT
   Pages, margins, sections, headers, objects

5. AUTOMATION
   TOC, captions, fields, Mail Merge, macros

6. COLLABORATION
   Comments, Track Changes, sharing, version history

7. RELEASE QUALITY
   Proofing, accessibility, security, PDF, verification
```

A beginner asks:

> “How do I make this heading blue and 18 pt?”

A skilled Word user asks:

> “Which style should this heading use?”

A beginner asks:

> “How do I push this text onto the next page?”

A skilled Word user asks:

> “Should this use a page break or a section break?”

A beginner asks:

> “How do I type all the page numbers in the contents page?”

A skilled Word user asks:

> “Is my heading structure correct so Word can generate the Table of Contents automatically?”

A beginner asks:

> “Why does Figure 12 now need to become Figure 13?”

A skilled Word user asks:

> “Why was this figure numbered manually instead of using a caption?”

The most important change is this:

> Stop thinking of Word as a page where you manually place and decorate text. Start thinking of it as a structured document system where styles, sections, fields, references, templates, and automation work together.

That mindset is the real path from beginner to Microsoft Word power user.

# Appendix A — Formatting Marks Explained

Formatting marks reveal hidden document structure.

Turn them on with:

```text

```

Common marks include:

```text
¶  Paragraph mark
·  Space
→  Tab
```

You may also see markers for:

- page breaks
- section breaks
- manual line breaks
- hidden text depending on settings

## Why they matter

If a blank page appears, formatting marks answer questions such as:

```text
Is there a page break?
Is there a section break?
Are there ten empty paragraphs?
```

This feature is one of the best troubleshooting tools in Word.

| Restart page numbers | Section Break |
| Different header/footer | Section Break |

| Different columns for part of page | Continuous Section Break |
| Start chapter on next odd page | Odd Page Section Break |

# Appendix C — Styles vs Direct Formatting

## Direct formatting

Changes the selected text/paragraph directly.

Example:

```text
Select heading → Bold → 18 pt → Blue
```

## Style

Applies a named reusable rule.

Example:

```text
Select heading → Heading 1
```

## When direct formatting is okay

Small exceptions such as emphasizing one word in bold.

## When styles are better

Repeated semantic elements such as:

- headings
- captions
- code blocks
- warnings
- quotations
- body text
